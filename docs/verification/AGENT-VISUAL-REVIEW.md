## 2. 发现与关闭记录

### VIS-REV-01 · MEDIUM · 已识别危险后的一般失败路径可能漏建人审任务

状态：**已关闭（只读复核）**。

依据：

- Product-Spec.md REQ-014 与 AC-070 要求文字或图片提示潜在危险时及时进入 HITL，不等待订单补齐。
- AGENT-ARCHITECTURE.md 第 4.1 节的图从 Understanding 进入 agent_decide，再由该决策进入 commit_handoff；第 4.3 节将技术错误和预算耗尽分别收口为 failed、budget_exhausted。
- 同文第 4.4 节已有结构化 risk_flags 和危险分流，但没有规定“已取得有效危险标记”与后续技术失败/预算耗尽的优先级。
- AGENT-ACCEPTANCE.md AC-070、FT-18 和 BUSINESS-SCENARIOS.md VIS-006 尚未覆盖此交叉时序。

触发路径：图文理解成功，当前有效分析记录疑似烧灼/熔化 → 进入下一决策节点时预算不足，或后续请求超时 → 依通用失败条款结束 run，可能只保存技术错误，处理权仍为 agent 且未建立 HumanReview。没有错误发信，但遗漏了已经满足条件的安全人审。

最小修订：有效危险标记一经识别，应由确定性终局路径优先建立/复用 HumanReview 并撤销自主处理权；后续技术失败或预算耗尽作为附加原因记录，不需再调用模型或增加预算。仍必须复核输入、证据及处理权栅栏：已停止、被新输入替代、被更正/撤销的旧结果不能借安全分流写回。没有成功识别危险的纯图失败不得伪造风险。补充“有效 risk_flags → 后续请求失败/额度耗尽”的验收分支，断言人审持久化、零追加模型调用及零业务/出站动作。

修后证据与复核：

- Product-Spec.md REQ-014 新增程序直接持久化危险人审的 MUST，AC-070 覆盖有效风险之后额度耗尽/技术失败，且未识别风险时不得编造危险。
- AGENT-ARCHITECTURE.md 第 4.1 节增加理解后的危险门，直接进入 commit_handoff；第 4.3 节明确其优先于普通 failed/budget_exhausted；第 4.4 节要求有效风险、HumanReview、处理权撤销和 handed_off 同事务保存，不等下一次 agent_decide。额外模型/工具调用为零，停止、过期输入、删除及人工处理权栅栏仍优先；数据库提交失败不显示人审成功。
- 第 4.4 节同时明确风险 active/resolved_by_human/corrected_by_human 生命周期及来源修订。人工完成回复不暗中清除风险，旧缓存不恢复已纠正风险，模型不能自行清除；与既有人工更正及下一新来信恢复规则一致。
- AGENT-ACCEPTANCE.md AC-070、FT-18 与 BUSINESS-SCENARIOS.md VIS-006 已加入有效风险后额度不足/技术失败、无风险纯失败对照、旧运行栅栏竞争及事务失败断言；BACKEND-ARCHITECTURE、CHANGELOG、HANDOFF 同步说明。

静态推演确认：原触发路径现在在风险落库时即原子进入人审，后续失败不再覆盖为无人审的普通失败；本文未运行上述故障测试。
