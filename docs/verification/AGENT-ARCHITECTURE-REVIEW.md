## 2. 已关闭发现

### AR-01 · HIGH · 业务结果先于等待注册可能漏唤起

初读证据：AGENT-ARCHITECTURE 原第 105 行仅在“存在匹配 WaitCondition”时排跟进，第 233 行才在终局保存等待。
反例时序：

1. Agent 提交内部退款申请，尚未提交本轮回复及等待条件。
2. 控制台抢先保存成功回执；因为等待尚不存在，事件不创建后继任务。
3. Agent 保存“申请受理、等待回执”和等待记录；没有后续事件时会永久等待。

仅令旧 run 过期仍不充分：若未持久登记后继触发，就会丢失继续处理的原因。
最小修订是让事件接收与等待注册线性化，并持久保存尚未消费的业务变化。
复核证据：架构 §3.2 当前第 105、118 行明确关联在办申请/事项、`wake_pending`、同序锁及版本补查。
事件先到由等待注册补查；等待先到由事件接收唤起；排队不算消费，人审屏障仍抑制自动处理。
验收证据：AGENT-ACCEPTANCE 的 FT-07 已包含两个提交顺序、去重及重启门禁。
状态：**CLOSED（设计）**；仍需真实 PG 事务屏障测试证明实现。

### AR-02 · MEDIUM · 固定 run 快照与 search 自行换版本冲突

初读证据：架构原第 74 行规定一轮知识快照；原第 253 行允许 search 重新取 head/profile；原第 231 行才定义整轮重建。
反例时序：第一次检索返回 R1，随后发布 R2；第二次工具自行读取 R2，模型仍携带 R1 片段与旧政策候选。
即使每次 SQL 检索内部一致，也不能保证一轮工具观察及政策判断使用同一快照。
最小修订是把换版本权收回编排层，search 只能返回固定上下文中的版本或 stale_release。
复核证据：架构 §7.2 明确 `ctx.release_id / embedding_profile_id`，规则服务服从同一 manifest。
工具前后检查 head，变化即拒绝；统一重建清除旧知识消息、摘要及候选 policy decision，最多一次且不重置预算。
已经合法提交的 operation 只作为历史账本保留；历史模式的重建仍不能越过原截点。
状态：**CLOSED（设计）**；FT-10 已加入两次检索之间发布及 Embedding 返回时变更，正式运行仍待实现。

## 3. 业务边界核对

| 核对点 | 设计证据 | 判断 |
|---|---|---|
| 七类业务 | Spec REQ-011；架构 §1、§5；验收 §5 | 保留正常自动路径、补问与例外路径，未统一降为 HITL |
| 申请与执行分离 | Spec 第 440 行；架构 §3.3、§6.1 | accepted 只代表内部申请；库存预留属于模拟履约事务 |
| 退款未知与改方案 | 架构 §3.3、§6.1；FT-03、FT-06 | unknown 不释放占用；查原操作和可取消性后才允许冲突方案 |
| 多订单与多包裹 | 架构 §3.1、工具表；SCN-008/022/025 | 事项、订单行、操作与包裹独立关联；不按邮箱或第一条记录推断 |
| 人工结案 | Spec AC-023；架构 §3.2 | 成功回执、已发送或模型建议均不能自动结案 |

自然语言中的同意、条件和事实仍须模型与业务回归判断；架构 §6.3 已披露确定性 guard 不能形式证明全部自然语言正确。
没有把模型自报置信度、检索相似度或历史客服话术当作交易授权。

## 4. 状态、运行与事务核对

| 核对点 | 设计证据 | 判断 |
|---|---|---|
| 身份/模式隔离 | 架构 §2、§8.1；Spec REQ-001/002 | sender 与 group_id 分开；历史、模拟、重置代次及未知身份规则明确 |
| 版本分工 | 架构第 93 行及 §3.2 | input、authority、case、UI row 各有含义；Agent 合法记忆更新不自我失效 |
| HITL 新轮次 | 架构 §3.2、§4.1；FT-02 | 人审结束旧图；human_reply 不立即运行，仅后续新接收客户来信恢复 |
| 全局单槽与租约 | 架构 §6.2/6.3 | AgentSlot 租约/fence 与事务资格复核明确；不靠进程内布尔锁 |
| 显式技术恢复 | 架构 §3.3/6.2；Spec §11.8 | running 中断需 retry；未领取 queued 可在 gate 允许时开始 |
| 出站与业务去重 | 架构 §6.1 | cycle 最终 outcome 唯一；command 去重加跨 run 的订单行补偿约束 |
| 锁序与提交 | 架构 §6.3 | 槽位、分支、会话、发布头、订单、执行/库存及任务顺序明确；外部调用不持事务 |
| 停止与晚到 | 架构 §6.2/6.3；FT-04/05 | 旧结果受 epoch、generation、fence 约束；已提交业务效果不被抹去 |
| 预算 | 架构 §4.3；Spec ASM-005/006 | 6 模型、12 工具、120 秒、16k/2k/80k、30 秒沿用；同 cycle retry 不归零 |

当前文本没有显式要求反向嵌套锁；领取/心跳只锁 slot/task 后结束，发布不持知识锁回取会话。
这只能说明设计锁序可实现，不能替代实际 SQL、外键隐式锁、锁等待与进程恢复验证。
