# Agent 架构验收映射与故障推演

版本：v1.1；日期：2026-10-07（北京时间）。基线：Product-Spec v1.13。
状态：开发前验收设计；本文没有执行测试，也不声明任何业务验收条件通过。
业务行为以 [Product-Spec.md](../../Product-Spec.md) 为准，整体分工见 [BACKEND-ARCHITECTURE.md](../architecture/BACKEND-ARCHITECTURE.md)，详细状态与事务契约见 [AGENT-ARCHITECTURE.md](../../AGENT-ARCHITECTURE.md)。
场景来源：[BUSINESS-SCENARIOS.md](../business/BUSINESS-SCENARIOS.md)、[数据契约](../../data/knowledge/v1/DATA-CONTRACT.md)、[连续流程清单](../../data/knowledge/v1/scenarios/journeys/README.md)。

## 1. 本文完成标准与验证边界

1. 将全部 82 个验收条件逐项映射到负责模块、关键不变量及未来验证方法；一项只有一个主映射，可由多个模块协作。
2. 为 30 个业务场景和 21 条连续流程建立分组入口；资料数量只代表输入覆盖，不代表系统已完成业务闭环。
3. 将竞争、重启、未知结果与知识撤销转成可控制时序的故障检查；后续开发计划据此分配实现和验证任务。
4. 为客户图片的文字提取、可见异常理解和有依据的售后分流建立 18 项专项入口；样本尚待制作，全部新增验收仍待实现/实测。

正式验证分四层：**契约**检查确定性规则；**集成**检查真实业务数据库与 API/worker；**模型**使用真实 Qwen 验证自主行为；**界面**检查 Art Design Pro 工作台及知识管理操作。
下表“验证方法”全部为未来要求。模型输出不得替代数据库断言，测试驱动不得把参考回复写成实际 Agent 回复；模型自评不能单独判通过。
历史评测只能读已获准且复核的真实前缀；本文只读取文档和场景清单，不读取 `.env`、原始客户目录或保留集内容。

## 2. 模块职责索引

以下是验收使用的职责简称，不预设代码目录或增加独立服务；首版仍为模块化单体、单主 Agent。

| 简称 | 主责与权威数据 |
|---|---|
| 接入/身份 | 导入校验、消息去重、稳定客户身份、模式与分支范围；不以 group_id 合并客户 |
| 会话/处理权 | 单会话主动处理者、版本、人审屏障、人工结案；处理权由业务数据库裁决 |
| 上下文/理解 | 可见前缀、案件记忆、结构化多诉求与证据；理解结果始终可修正 |
| 图片/证据 | 受控原图与派生图、逐图状态、来源及修订、可见性与撤销；联合理解仍使用 Qwen3.7-Plus 的 Understanding 节点，不增加视觉 Agent 或默认 OCR 服务 |
| Agent/预算 | LangGraph 理解节点和动态工具循环、停止/失败、调用及 token 预算；run_id 等于 graph thread_id |
| 工具网关 | Schema 校验及服务端注入身份、模式、截点、版本；拒绝模型扩大权限 |
| 业务账本/模拟控制 | 资格、申请、额度/数量约束、执行单、库存与事件；Agent 与控制台写权限分开 |
| 知识/解析 | 原件、不可变版本、精确适用范围、发布快照、向量空间、撤销与引用有效性 |
| 提交门 | 最终回复/对照产物、来源复核、处理权与版本复核、唯一出站事实 |
| 观测 | run/trace 关联、实际 usage、隐私过滤、离线降级；不能充当业务账本 |
| UI | 工作台、人审、场景控制台、知识维护、错误/受限状态及引用展示 |
| 评测/清理 | 测试输入隔离、断言记录、分支重置、正文副本清理与删除防复活 |

## 3. 跨模块不变量

- 所有查询与写入绑定客户、演示集合、模式、分支和必要截点；`historical_replay` 缺可信历史时返回不可用，不回退模拟数据或当前快照。
- 业务账本、处理权及最终提交记录是权威；检查点、摘要、SSE 和 Langfuse 均不能推翻已提交事实。
- 可信 RunContext 由服务端构建；input_revision、authority_epoch 与 case_revision 分开校验，Agent 自己的合法案件记忆更新不被误判为外部新来信或接管。
- HITL 持久化暂停并结束本轮；人工回复后必须等下一封新客户来信，启动新 run，禁止恢复旧工具动作。
- 进程中断后的在途 Agent 标为中断/待恢复，显式重试才继续；正常等待业务结果的新事件可以触发新 run，两种恢复不得混用。
- Agent 只创建/取消内部申请，查询关联执行记录；模拟 ERP 建单、履约推进、库存变化只允许控制台/测试驱动合法操作。
- 去重同时覆盖请求、触发事件、业务事项和受影响数量/金额；更换 run_id、request_id 或工具调用 ID 不能重复补偿。
- 写工具和回复提交均重新校验版本、处理权和资格；停止不撤销此前合法提交的业务事实，晚到写入不得绕过栅栏。
- 单轮最多 6 次模型、12 次工具、120 秒；理解、格式修复、重试和摘要均计入，同工具同参数连续两次无进展则停止。
- 单次输入初值 16k tokens、输出最多 2k，累计输入输出最多 80k；请求前预留最大输出，单次网络超时 30 秒，限流/超时仍消耗次数与时间。
- 知识使用同一发布快照和向量空间；最终提交事务锁定相关发布头并检查撤销、删除及必须生效的版本，检查与提交不可分成两个事务，不能信任旧事务或缓存中仍可见的正文。
- 场景未来事件、完整故事、参考回复和期望答案仅供驱动/评测；每一步须由实际 Agent 行为满足屏障后推进。
- 客户图片限受控 JPEG、PNG、静态 WebP 字节，附件、CID 与纯图片邮件遵循同一身份和去重规则；不执行 HTML 或访问远程图片/二维码链接，客户 PDF、视频和音频仍未读取。知识 MinerU 解析流程独立。
- 文字读数和视觉观察带原图/版本、可用的位置依据、质量与歧义；客户陈述、观察、原因推测、工具核验和人工决定分开。候选只在当前客户内精确查单，不遍历近似号；照片不证明根因、责任、真伪、资格或履约。
- 正常外观不否定功能故障，局部未拍到不证明缺件；危险迹象无需等待订单补齐即进入 HITL，停止使用提示须有已核准指引，不要求通电或拆机。普通信息不足先补问，不强制所有图片人审。
- 当前有效 Understanding 产出经 Schema/来源校验的 risk_flags 后，程序同事务保存风险、建立/复用 HumanReview、撤销自动权并将 run 标为 handed_off，不依赖后续模型决策或新增模型/工具调用；额度不足或后续技术错误不能覆盖为普通 failed/budget_exhausted。停止、输入过期、删除和人工处理权栅栏仍优先；从未识别有效风险的纯图技术失败不能伪造危险，事务未提交不能显示人审成功。
- 原图、裁剪、提取正文、观察和分析缓存均继承客户/模式/分支/历史截点/用途隔离，默认不进入共享知识库；历史可见图片可在当前分析但须标明分析时间，不取未来重发或未来结论。相同内容摘要不能替代授权。
- 所有视觉请求、局部复核、修复与重试共用原单轮预算；ASM-011 初值为每封最多 4 张、单张 10MiB/20 百万像素、合计 20MiB、每轮最多 6 个图像视图。超限和未读部分显式记录，未知 usage 不计零，无图邮件不新增视觉调用。
- 新来信、接管、人工更正、停止、重置与移除使相关旧结果失效；解析完成或更正本身不绕过 HITL。撤销立即阻止使用，彻底删除覆盖项目持有原图及派生正文副本，晚到写与备份不能复活；既有业务只保留无正文审计且不能重复办理。
- 图中文字不授予任何权限；观测默认不导出原图/base64、可访问链接或敏感提取正文，前端不暴露服务器路径/凭据。真实样本先经隐私复核，人工标签和参考答案不得进入模型输入。

## 4. 全部验收条件的主映射

| 验收条件 | 源需求 | 负责模块 | 关键不变量 | 将来验证方法 |
|---|---|---|---|---|
| AC-001 | REQ-001 | 接入/身份 | 同模式集合内同一规范身份复用会话 | 契约+集成：两封同身份来信，断言同 conversation_id 与首封可见 |
| AC-002 | REQ-001 | 接入/身份 | group_id 仅隔离分组，不是客户身份 | 契约：共享 group_id 的不同 sender_key 不合并、不共享订单 |
| AC-003 | REQ-001 | 接入/身份 | 重复源消息不新增消息或触发任务 | 集成：重复导入与并发导入，核对消息/触发唯一记录 |
| AC-004 | REQ-002 | 上下文/理解 | 当前历史前缀不含未来来信、客服回复、结案备注 | 契约+集成：截取实际模型请求与当前会话 API 响应检查禁入标记 |
| AC-005 | REQ-002 | 上下文/理解 | AI 对照回复不成为真实历史事实 | 集成：故意生成不同建议，下一截点只继承真实客服前缀 |
| AC-006 | REQ-002 | 工具网关 | 订单快照与知识共享 as_of，不回退未来数据 | 契约：晚于截点快照、缺截点分别返回不可用/输入错误 |
| AC-007 | REQ-003 | 提交门 | 完整校验后的回复自动产生一封模拟出站 | 模型+集成：无需审批完成正常回复，核对出站及来源标签 |
| AC-008 | REQ-003 | 提交门 | 同一最终提交仅有一个出站事实 | 集成：同请求重复/并发提交均返回原产物，出站计数不变 |
| AC-009 | REQ-003 | 上下文/理解 | 多轮实际模拟回复及失败反馈可追溯 | 模型：至少三封来信，核验实际请求及已尝试步骤表述 |

| AC-013 | REQ-005 | 知识/解析 | SKU/章节范围显式匹配后再排序 | 契约+检索集成：相似错误型号不得进入适用证据 |
| AC-014 | REQ-005 | 知识/解析 | 德文问题能命中中文目标证据 | 检索集成+界面：冻结标注查询，前五含目标片段且引用可打开 |
| AC-015 | REQ-005 | 提交门 | 无对应可读取内容时，元数据不是视频/附件内容证据；已实际读取的受支持图片另行溯源 | 模型：仅给标题/附件元数据时不得声称已观看视频、读出发票或识别图片；与 REQ-014 的真实图片字节输入作对照 |

| AC-017 | REQ-006 | Agent/预算 | 缺订单属于可补问信息 | 模型：生成针对性补问，不编造专属排障，不无理由 HITL |

## 6. 架构故障时序检验设计

统一方法：用可控屏障暂停于“读上下文后、模型返回前、业务提交后、checkpoint 前、最终提交前”等位置，记录提交先后与拒绝原因；不靠随机 sleep 偶然触发竞态。
每项均需保存事件序列、业务版本、run/operation 标识、账本前后快照、出站计数与调用计数；以下均待正式系统实现后执行。

| 编号 | 故障时序 | 必须观察到的结果 |
|---|---|---|
| FT-01 | 旧 run 读上下文→新来信入库/人工接管（分别及组合）→旧模型返回 | 新来信只归原客户；旧回复及未执行写动作失效；人工持权时不启动自主处理，保留旧运行停止原因 |
| FT-02 | 人工提交 human_reply 与 business_event 同时到达；分别交换事务顺序，再加入新客户来信 | 两种事件顺序都不能越过人审屏障；只有人工完成后新接收的客户来信触发新 run；过期人工表单须重新核对，不能吞掉未覆盖来信 |
| FT-03 | run A 建补件申请→超时/新 run B 换 request_id→提出同数量退款或补件 | 按同一业务事项和订单行占用判断，不依赖 run 去重；原申请取消确认前冲突方案不能生效，额度/数量不重复占用 |
| FT-04 | 写工具停在提交前→停止/接管/删除提交→旧写工具继续；另测写已提交再停止 | 栅栏提交后旧写被拒；此前合法申请继续可查，不因停止抹除或再建；模拟履约库存与内部申请预留分别核对 |
| FT-05 | 内部申请或最终回复 DB commit→进程崩溃，LangGraph checkpoint 未完成→重启 | 重启只展示账本并标记中断，不自动调用模型；显式 retry 先读取原结果，未提交终局才可继续，已提交出站不重复 |
| FT-06 | 业务事务可能提交但响应丢失→结果标未知→重试/查询仍失败→后续可对账 | 保留原操作号及占用，不把查询失败当未执行；未知未解除前不得创建第二笔或释放约束，证实结果后按原申请跟进 |
| FT-07 | 分别令业务结果先于/后于WaitCondition注册提交，再投递重复/乱序/无关事件，随后刷新或重启 | 注册wait与事件接收同序锁并比较业务版本；先到结果也登记wake_pending/后继触发，不会永久等待；去重跟进，排队不算消费。中断run需显式retry，未领取新任务仅在gate=open时调度 |
| FT-08 | 历史截点 A 生成 AI/人工对照→推进 B；加入未来快照、未来资料、Mock 及完整故事哨兵 | B 仅从真实可见前缀重建；工具和浏览器响应不泄漏未来或对照事实；历史缺证据保持未知，无模拟业务写入 |
| FT-09 | 检索旧快照→政策发布/资料下架→旧事务仍可读→提交回复/售后动作；旧入库任务随后完成 | 新事务复核撤销及必须生效版本，失效依据不能提交；政策规则/说明同版；晚到构建不重激活，预算不足时停止/人审 |
| FT-10 | 新 Embedding/切分构建仅部分成功→尝试发布→完成后切换→回滚；再在同一run两次检索之间及查询Embedding返回期间切换head | 原索引持续可用，同维不同模型隔离；旧ctx返回stale_release，统一重建清除旧知识消息/摘要/候选policy decision且预算未重置，不能混R1/R2。不完整构建不可发布，回滚不能恢复撤销资料 |
| FT-11 | 删除知识或模拟分支→对象/缓存/检查点清理部分失败→旧checkpoint put/pending-writes、模型结果及trace缓冲晚到→恢复删除前备份 | 持久写门同事务拒绝旧写，等待写入者静止后清理；仅引用未展示但曾给模型的正文也按依赖清理。共享PDF无法安全拆分则阻塞而非误删其他文档；失败不显示完成。恢复先应用独立删除登记，旧引用只留无正文占位 |

| FT-13 | 视觉请求读入图文后暂停→新客户来信/人工接管/手动停止分别提交→视觉返回；接管组再追加人工回复及业务事件 | 旧结果不能更新当前候选/记忆/回复或触发内部申请；已接管 run 终止，人工回复/图片完成/业务事件均不自动恢复，只有之后新客户来信可启动新 run |
| FT-14 | 旧视觉请求或缓存回写在途→人工取得处理权并更正字段/观察，或分支重置→旧结果晚到；另测无处理权/旧版本更正，再运行合法新请求 | 无处理权及旧版本更正拒绝；合法更正修订和重置栅栏原子生效，旧结果不能覆盖新事实或重建已清空数据；新 run 只用可见且有来源的有效修订，更正不越过人审屏障 |
| FT-15 | 草稿移除/已提交证据撤销/彻底删除分别发生→视觉、缩略图、裁剪、checkpoint、trace 写入晚到→清理局部失败→恢复旧备份 | 撤销立即阻止新读取及依赖提交；持久写门拒绝旧内容，项目副本验证完成前不宣称删除。恢复先应用删除登记，既有申请只保留无正文审计、不释放已发生操作的去重约束或重复办理 |
| FT-16 | 4 张合法图片联合理解接近 token/时间上限→请求局部复核/修复/重试，另测第 7 个视图、5 张图、文件超限、provider usage 缺失 | 请求前执行原预算及 ASM-011 门禁，重试不另开预算；未知 usage 保守预留且不记零。超限输入、停止原因和未覆盖图/区域可见，不静默漏读、不自动外发 OCR 服务 |
| FT-17 | 当前客户图分析入缓存→他客/另一分支/知识用途提交同摘要图；历史截点后重发高清图并产出分析→回到早期截点预览/理解 | 原图和派生结论均按授权范围拒绝跨域复用；早期截点只用当时可见受控字节，不能用高清重发或未来缓存；合法回放重新分析带分析时间且不改真实前缀 |
| FT-18 | 分支A：多图部分失败、关键图未完成、图内退款指令及截图/回执冲突；分支B：当前有效 Understanding 形成已校验 risk_flags→决策额度不足或后续技术失败；分支C：纯图技术失败且从未形成有效风险。B另与停止/新输入/删除/人工持权争用及事务失败交错 | A逐图保留真实状态、无依据不下结论，图内指令无权且截图不覆盖回执。B同事务保存风险、建立/复用 HumanReview、撤销自动权并 handed_off，不依赖 agent_decide 或新增模型/工具；后续错误另记，不覆盖人审，不发出通电/拆机指令。栅栏先提交则拒绝旧结果，事务未提交不得显示接管成功。C保持 failed，不编造危险 |

FT-09 同时验证“发布变化”与“撤销资格”的区别：普通新版本不抹去已执行账本及承诺；必须生效的新规则与旧承诺冲突时进入人工判断。
FT-11 的删除范围为项目持有副本；外部原件、已外发内容、供应商留存与离线备份分别说明处理边界，不能以本地清理冒充全部外部删除。
FT-13 至 FT-18 沿用统一可控屏障，另保存 attachment/version、分析与人工修订、输入视图清单、可见截点及覆盖状态。FT-15 同样遵守上述外部删除边界；FT-16 的上限是工程默认，不是厂商能力声明。
