# 首批业务场景与数据准备

版本：v1.4；2026-10-07（北京时间）。关联 [Product-Spec v1.13](../../Product-Spec.md)、DATA-PREPARATION、DATA-CATALOG；技术分工见 BACKEND-ARCHITECTURE，验收主映射见 [AGENT-ACCEPTANCE.md](../verification/AGENT-ACCEPTANCE.md)。

七类业务均为首版目标。本文规定业务分工与验收场景。首批知识、模拟规则及 51 个静态场景输入已制作于 data/knowledge/v1/；包含 SCN-001 至 SCN-030 各一个具体分支和三品牌各七类基础输入。业务工具、加载执行器与运行测试尚未实现，不能把资料检查当功能通过。

已进一步补齐 21 条连续业务流程（每类 1 主流程 + 2 分支），见 data/knowledge/v1/scenarios/journeys/README.md，共 287 个后续步骤、88 封客户来信及 50 段隔离参考回复。与原 51 个环节样例分别计数；总计 72 个场景输入。每条写到人工结案，但未执行 Agent。

客户图片文字提取、可见异常理解及有依据的售后分流已纳入首版。第4.1节18项图片专项已在Phase 1冻结分支及35个合成AI样本、完成108次最终真实请求，但**验收未通过、人工标签待核对**，见[专项报告](../verification/VISUAL-VALIDATION.md)。运行时/UI/删除分支留后续阶段，不改变上述30个SCN、21条JRN和72个原批次输入数量。

## 1. 七类业务及完成条件

“内部申请已提交”“人工业务操作已完成”“客户问题已解决”分别记录；最终结案由客服确认。正常回复和内部待办可自动生成，人工执行待办不等于 HITL 接管。

| 类别 | Agent 职责 | 模拟业务执行与结果 | 关键边界 |
|---|---|---|---|
| BIZ-01 产品咨询 | 查单定位商品，检索说明/兼容资料，回复使用或配件购买咨询 | 查询产品与配件目录 | 型号不明先补问；购买咨询不自动免费补寄 |
| BIZ-02 故障排查 | 复用已尝试步骤，提供适用指导，必要时提出售后方案 | 客户反馈、模拟客服/工程师意见作为后续事实 | 无可靠步骤或危险现象转 HITL，不反复要求无效操作 |
| BIZ-03 物流查询 | 查询原件、退件、换出或补发包裹，解释状态并跟进 | 场景控制台推进物流/查件记录 | 单据创建不等于揽收；匹配具体订单和包裹 |
| BIZ-04 退款 | 核对诉求、金额、规则和既有退款，提交内部申请，查询回执 | 模拟人工在原销售渠道处理退款并回传结果 | 受理不等于退款完成，不能重复补偿 |
| BIZ-05 退货 | 判断规则，提交申请，取得有效退货资料后提供指引 | 模拟退货单、寄回、签收/验货结果 | 退货不必然已退款，是否先退后退钱由场景规则决定 |
| BIZ-06 换货 | 核对型号/库存/地址与客户选择，提交申请并跟进 | 模拟人工建立关联订单的换货/补发单及需要的退件 | 先退后换、先换后退等由绑定规则明确，不一律硬编码 |
| BIZ-07 补寄配件 | 判断必要性与兼容性，生成内部待办，按原订单和待办查询结果 | 模拟人工建补发单，再推进发货/物流记录 | Agent 不代替人工创建模拟 ERP 单；查询不到时可人工补充关联 |

一个发信人保持一个会话，内部按订单和售后事项分别跟踪。订单号及 SKU 已知就复用；明确可补充的信息先补问，无可靠决策时才 HITL。

## 2. 数据依据与资料含义

当前基线来自 2026-10-06 和 2026-10-07 的生产只读查询，见 DATA-PREPARATION 和 DATA-CATALOG。旧本地准备包只保留探索历史，不作为新工作集，也不直接复用其 rag/dev/eval 分组和答案。

| 来源 | 确认的含义 | 可用方式 |
|---|---|---|
| 售后登记及已核对状态 | 定时任务登记首封正文；客服核对正文完整性、订单和品牌/SKU 关联 | 商品身份与首封问题线索，不证明处理成功 |
| 快捷回复 | 客服自认为常用的表达与场景 | 沟通风格参考，不当正式政策或当前执行事实 |
| YouTube 视频目录 | 主要给客户操作/排障/换配件，也供客服查看 | 先核对内容与型号；仅题名时保留候选链接 |
| 系统上线后首封会话 | 优先作为从起点开始的多轮候选 | 核对正文、引用重复和往来完整性，不按最新一封标签过滤 |
| 上线前 Outlook 历史会话 | 可能缺少早期交互 | 显式标注缺失历史，不补造为真实事实 |
| 生产订单和登记商品 | 商品、地区、数量等业务原型 | 原快照和模拟分支分开；登记品牌与邮箱冲突需保留 |
| 拟定政策及业务模拟器 | 团队编写的试运行条件和执行状态 | 退款/退换/补发全流程可模拟，不要求生产存在相同接口 |

目录阶段不导出正文；后续制作已将原始正文保存在受控 Git 忽略目录，先按客户、订单和近重复线索分组，再提炼 5 个 RAG 候选摘要。公开资料包不含原始正文；独立评测组未审读标注，不报告真实准确率。

## 3. 模拟流程与已准备的数据

采用 **Agent 决策/内部待办 → 模拟人工业务操作 → 关联执行记录 → Agent 查询跟进**。场景控制台扮演客服、ERP、平台和仓库的状态输入端，不建设完整 ERP，不让 Agent 调用控制台伪造成功结果。

下表数据已在首批资料及连续流程中准备；运行时加载、校验、状态推进和界面尚未实现。图片专项的新增样本仍按第4.1节单独制作。

| 数据对象 | 已准备的内容与运行时职责 | 来源与状态要求 |
|---|---|---|
| 模拟订单 | 原订单、商品行、金额/币种、购买与签收时间、客户归属 | 真实原型可派生；构造字段明确标记，保留独立分支 |
| 试运行政策 | 适用品牌/渠道/地区，退换窗口、费用、退款范围与例外 | 已有 policy-profile 1.0.1 模拟规则，数值以该包为准；旧 DEMO-POLICY-v1 不再作为基线，现有模拟规则也不等于三品牌正式政策 |
| 内部售后待办 | 售后类型、订单行、方案、客户选择、等待条件 | Agent 可创建，须去重；不等于外部单据或已发货 |
| 模拟执行记录 | 人工创建的补发/换货/退货/退款单及受理、失败、取消等结果 | 关联原订单与内部待办；一单可多次售后，不能随便取第一条记录 |
| 配件与库存 | 兼容型号、地区规格、数量及可用/未知/缺货 | 不按视频标题推断配件通用；履约阶段校验并占用库存 |
| 物流与回执 | 原件/退件/补发件的包裹、单号、运输及退款结果 | 区分已建单、已发货、已签收；查询失败和确无记录分别返回 |

正常等待由后台任务同步模拟记录，相关状态变化再唤起 Agent；客户追问时按需查询，不让模型不停轮询。人工手工关联/回填是查询链不完整时的备用入口，不要求每次复制单号。

内部待办去重及额度/数量约束由程序执行；模型不得修改规则、增加库存或制造回执。HITL 期间只记录事件；人工回复后的下一封新客户来信才自动恢复。

## 4. 首批场景清单

共 30 个场景，均列入首版验收；每类同时有可自动处理路径和补问/例外路径。每条 fixture 包含客户输入、可见历史、初始业务数据、政策/资料版本、后续模拟事件、期望动作及禁止动作。

| 编号 | 类别 / 输入情境 | 期望结果与禁止行为 |
|---|---|---|
| SCN-001 | 产品咨询：型号明确，询问功能设置 | 检索适用说明并回复，附来源 |
| SCN-002 | 产品咨询：缺订单或一单多商品 | 先复用历史，再补问必要信息；不猜型号 |
| SCN-003 | 产品咨询：购买备用配件，兼容信息不足 | 查询商品/配件关系和库存，必要时人审；不自动免费补寄 |
| SCN-004 | 故障：遥控器配对失败，有适用步骤 | 自动指导并记录已尝试操作 |
| SCN-005 | 故障：上一轮步骤无效 | 采用有依据的新步骤或衔接售后，不重复旧建议 |
| SCN-006 | 故障：多次无效、资料冲突或客户报告冒烟等危险现象 | HITL，给出适用的停止使用提示，不继续要求通电试验 |
| SCN-007 | 物流：有效原订单/补件包裹运输中 | 查询对应包裹与更新时间，回复实际状态，不编造送达保证 |
| SCN-008 | 物流：客户质疑单号或同一订单有多个包裹 | 检查包裹关联，澄清查询对象；不串用另一个包裹 |
| SCN-009 | 物流：延误、投递失败或显示签收但客户未收到 | 依适用规则提交/查询查件待办并跟进；争议未解决时 HITL |
| SCN-010 | 退款：满足政策，客户明确申请全额退 | 校验实付/余额和退货前置条件，提交一次内部退款申请，模拟人工执行后查询回执答复 |
| SCN-011 | 退款：部分退款方案尚未获客户同意 | 先说明具体金额/币种并取得选择；客户同意后提交内部申请，模拟执行业务 |
| SCN-012 | 退款：超额度、已退款、余额不足或币种政策缺失 | 拒绝重复或越界写入，解释已知事实，争议/例外转人工 |
| SCN-013 | 退货：窗口内且原因明确 | 提交内部申请，查询模拟退货单后提供费用/指引并等待寄回 |
| SCN-014 | 退货：缺商品数量、原因或寄回凭据 | 有针对性补问，不将缺字段当资格拒绝 |
| SCN-015 | 退货：超窗口或仓库收件/质检有争议 | 保存证据并 HITL；无收件结果不触发依赖收件的退款 |
| SCN-016 | 换货：同型号、有库存，退回条件满足 | 提交内部换货申请，查询模拟人工建立的换货/补发记录及物流；不在建单时声称已发出 |
| SCN-017 | 换货：型号/地区规格或地址不完整 | 精确核对并让客户确认地址，未确认不发起换出 |
| SCN-018 | 换货：缺货、退件未到或替代型号争议 | 等待、给出可选方案或人审；不自动替换型号 |
| SCN-019 | 补件：确认缺件、兼容且有库存 | 提交指定配件的内部待办；模拟人工建补发单后按原订单和待办查询结果 |
| SCN-020 | 补件：部件编号/规格不清，可能附着在主件上 | 查询订单/说明、补问确认；不按通用名称随意补寄 |
| SCN-021 | 补件：欧规/英规不符、库存不足或重复申请 | 阻止错误/重复补寄；更正须关联原单，例外人审 |
| SCN-022 | 同一发信人同时追问两笔订单，业务不同 | 同一会话分别维护物流和售后待办，不遗漏、不串单 |
| SCN-023 | 故障处理转退款/换货，客户改变选择 | 保留排查历史；检查旧操作能否取消与是否有既有补偿，再按新选择推进 |
| SCN-024 | 退货收件后退款 | 模拟收件合格后提交一次退款申请，等待并查询模拟执行回执；未收件不得提前声称完成 |
| SCN-025 | 补寄完成后继续追问物流 | 查询新补件包裹，沿用同一客户上下文，不重新索要已知订单 |
| SCN-026 | 写工具超时且结果未知，重复点击/重试/重启 | 使用同一操作号查询/对账，不以新键盲目再退款或再建单 |
| SCN-027 | 创建申请后等待外部事件 | 明确等待退款结果/收件/库存/物流；模拟事件推进后自动重新判断，重复事件不重复处理 |
| SCN-028 | 任一业务 HITL 后又收到邮件/状态事件 | 人审期间只追加信息；人工回复后下一封新客户来信恢复，状态事件不抢占人工 |
| SCN-029 | 历史回放缺少退款/物流结果，或有未来快照 | 返回未知/对照建议，不注入 Mock 事实，不执行写工具、不读未来资料 |
| SCN-030 | 客户已请求退款，同时又要求对同一商品换货/补件 | 识别方案冲突、核对已执行及处理中记录，补问或人审，不重复补偿 |

额外的通用验证贯穿这些场景：不同客户不可串单；修改地址使旧确认失效；旧运行不可覆盖新来信；跨语言回复；附件未读不视作证据；演示重置后不残留旧操作；所有状态均明确标记真实快照或模拟。

同一批 fixtures 增加上下文理解和观测断言：一封邮件可有多个诉求，“若仍不到就退款”保留条件，客户改变方案或只补充信息时正确更新；每轮关联理解/工具/结果 trace，脱敏与 Langfuse 离线行为按 Spec AC-045 至 AC-052 验证。

### 4.2 图片样本冻结与评测规则

所有 VIS 当前仅设计。后续制作使用合成或已获准且完成隐私复核的实际图片字节；每个样本记录内容摘要、格式/尺寸/像素数/大小、来源许可、客户/模式/分支/用途、接收时间和可见截点，以及图与消息、商品的关联。保留原图及各输入视图的版本和对应关系，只有元数据的样本仅用于未读取边界，不能当识别成功样本。

冻结时将人工复核标签与 Agent 输入物理/逻辑隔离：标签包括可读字段及容许歧义、可见观察及不可判项目、可接受分流及依据、禁止动作；不能把标签、参考回复、完整故事或未来材料放入模型请求、RAG 或当前会话 API。模糊或无法达成人工一致的项目标不确定，不强造唯一正确答案。

评测分开报告四类结果：字段精确匹配/歧义保留，观察误报/漏报，分流是否有充分依据，危险及越权禁止动作是否出现；另核对隔离、预算、时序、清理、隐私和 UI 的确定性断言。按品牌和难例分组保存样本数与失败，不用平均分抵消危险失败。每次保留模型/提示词/预处理配置、实际输入视图、工具与业务结果、耗时及完整或未知 usage，并按 [AGENT-ACCEPTANCE.md](../verification/AGENT-ACCEPTANCE.md) FT-13 至 FT-18 控制故障顺序。

AI 行为开发样本至少连续重跑 3 次并逐次保留失败；这只能说明该冻结开发集的稳定性。未经独立复核和隔离的保留集不能用于报告生产准确率；现有知识检索或模型工具烟测不能替代本专项，也不能把本表的期望行为标为已通过。

## 5. 事件、记忆与完成语义

- 会话状态负责谁处理；内部待办负责尚需完成什么；模拟执行单负责业务实际推进到哪里。
- 售后登记已核对、内部申请已提交、ERP 售后单已完成、运单已生成，都不能单独证明退款成功或包裹已发出。
- 人工执行待办时 Agent 可保持自动处理权；回传/查询到变化后跟进。HITL 是整个会话暂停，业务事件不得越过该恢复条件。
- 记忆保留订单/商品、已尝试步骤、客户选择、内部申请、执行单关联及下一等待条件；状态结论仍查询业务记录。
- 历史回放只读当时可见资料，不执行写工具或注入模拟结果。需要探索另一条处理路径时创建独立交互模拟分支。
- 真实历史、项目拟定政策、自编测试知识及模拟执行事实分别标记；历史客服承诺不是已执行回执。
- 客户图片内文字、客户陈述、视觉观察、推测、业务核验及人工修订分开保存；图像不是责任/真伪/交易资格或履约证明。撤销图片即阻止后续使用，彻底删除按项目持有副本验证，业务审计不因删除重做。
