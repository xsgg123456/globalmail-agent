日期：2026-10-08。依据：DEV-PLAN Phase 3、Product-Spec REQ-001/002/003/007/008/009、AGENT-ARCHITECTURE 第2/3/6/8节。状态：四步技术验证及最终独立两阶段审查通过，待用户查看。

## 有序任务与完成标准

1. 会话、受控 JSON 导入与回放：独立持久身份/消息/游标及来源案件事实；同一模拟邮箱追加、不同身份不合并、同源消息去重；当前响应和案件事实只含可见真实前缀。导入拒绝未来事件、答案及任意文件路径，未经复核身份只允许独立历史案例。
2. 人审与版本协议：接管、保存草稿、完成人工回复、人工结案及新来信重开；写操作携带幂等键及资源版本，人工回复额外检查输入版本。人审/人工待客户期间业务通知只记账，只有后续接收的新来信恢复资格；历史人工审阅不进入真实消息前缀。
3. 持久任务与事件：每次有效触发唯一 cycle/run/job；Agent 单槽与知识独立槽、数据库时钟租约和 fence；停止/接管/新输入拒绝旧执行；失效租约与重启中断须显式重试且沿用原 cycle。事件在会话锁内递增 seq，同事务入库，SSE 支持断线补读。
4. 三栏工作台：复用 Art Design Pro 和 Element Plus，接通创建/导入/追加/推进/接管/草稿/回复/结案/停止/重试，正文纯文本展示，保留错误输入；刷新和 SSE 订阅无任务副作用。
5. 独立两阶段审查与四步验证：真实隔离 PostgreSQL 测幂等、历史隔离、人审竞争、单槽/租约/中断/重试和事件补读；Python 编译、全套后端/前端测试及构建、浏览器操作与窄屏/明暗检查。保存命令、结果和范围限制。

## 边界与协作

不在本阶段接模型、业务查询、图片理解或完整删除。不生成假自动回复；任务协议 runner 完成后准确显示“任务协议已验证，模型尚未接入”。新来信自动建立持久任务，页面不提供逐封审批。

后端会话负责人拥有 domain、受控导入、会话/回放/人审服务、schema/migration、会话/事件 API 和相应测试；前端负责人拥有新增会话组件/API/composable 及工作台页面；主 Agent 拥有 worker 调度/租约、集成启动、交互与故障验收、文档及提交。共享表/API 由后端负责人先给出精确契约再联调，互不覆盖同一文件。审查由 fresh code-reviewer 执行。
