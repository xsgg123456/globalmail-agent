范围限制：所有演示推理、提示词、工具结果及指标标明构造；本轮不把旧后端写工具关闭说成已完成。持续人工模式的手动结案保留；解除后如何自动恢复仍待业务对齐。引用Vite自定义事件仅用于本地测试命令传到预览，见[官方插件API](https://vite.dev/guide/api-plugin#client-server-communication)。

验证中的修复范围：启动时同时清理旧PreviewBusiness/PreviewSimulation页签和搜索历史，保留有效页面及参数；两种Vite模式共用生成声明时，显式声明既有Element服务的自动导入，避免预览只扫描部分页面导致正式模板类型缺失。采用[unplugin-auto-import官方custom imports配置](https://github.com/unplugin/unplugin-auto-import#configuration)，不改正式页面行为。

独审发现后的修复验收：普通物流工具返回未知、失败或无可核实状态时，也必须保存内部建议并转人工，不能用“待核实”的客户草稿自动出站。HTTP/API注入此类Mock值与有据运输状态分别验收，不能只检查订单接口是否报错。

缺订单演示也需脚本可达：Mock查询数据增加lookupNotFound布尔开关，与lookupError查询失败分别呈现；它只改变预览工具返回，不改会话订单归属、不增加正式接口。

物流依据进一步收敛为结构化shipmentState（in_transit/delivered/unknown）和补充记录shipment，不能从自由文本或旧扫描关键词推断成功；仅改补充记录的测试命令使状态变unknown，须显式提供新状态才视为当前快照。已解决会话的接管按钮和handler均禁用/拒绝，不借接管隐式重开。

本轮五步已交付：[实测记录](../verification/UI-BUSINESS-SCOPE-PREVIEW-VALIDATION.md)、[最终独审](../verification/UI-BUSINESS-SCOPE-PREVIEW-REVIEW.md)Stage 1/2均PASS。82/82前端测试、两模式编译和修改范围ESLint通过；遗留“等待业务”筛选已删除并独立GUI复核。15175恢复八客户/十三轮干净样例，临时视口已恢复；无Git暂存/提交，不推进正式后端Phase。
